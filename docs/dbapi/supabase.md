# dbapi のために Supabase 側で行う作業一覧

このドキュメントは、`docs/dbapi/requirements.md` で確定した仕様を実現するための **Supabase 側タスクのみ** を記載する。

## 1. 認証・ロール設定

1. Supabase Auth を利用した認証基盤を有効化する。
2. `app_metadata` 方式でロール管理を実装する。
3. ロール値として以下の3種を運用する。
   - `Admin`
   - `一般ユーザー`
   - `DiscordConnector`
4. ロール付与・変更はサーバー側の管理経路（管理者操作）でのみ実施する。

## 2. RLS 設定

1. `members` テーブルで RLS を有効化する。
2. 以下のポリシーを実装する。
   - 一般ユーザー: 自分の行のみ `SELECT/UPDATE`
   - Admin: 全行 `SELECT/UPDATE`
   - DiscordConnector: `users` テーブルの `display_name` 更新のみ許可
3. アプリケーション層のチェックに加えて、DB 層（RLS）で必ず制御する。

## 3. ユーザー紐付け整備

1. 初回登録時に作成された `members.member_id` を、ログイン中アカウントの認証情報へ紐付ける。
2. RLS から `members.member_id` で本人判定できるよう、紐付けデータを整備する。

## 4. データ更新運用整備

1. `updated_at` が更新時に自動更新されるよう設定する。
2. 監査ログは現時点では導入しない。

## 5. 検索・並び替え向け最適化

1. フィルタ・ソート対象列に必要なインデックスを設定する。
   - 想定例: `grade`, `some_allergy`, `name`
2. 想定データ件数（最大150件程度）を前提に、運用上問題ない応答性能を確認する。

## 6. マイグレーション管理

1. 上記設定（RLS/ポリシー/トリガー/インデックス）を Supabase migration で管理する。
2. 開発・検証・本番で同一スキーマを再現できる状態を維持する。
