# 2.7 Units Generation — 作業単位

- 段階: Phase 2 Inception / 2.7
- 状態: **承認済み**（2026-09-03）
- 入力: `requirements.md`・`components.md`（いずれも承認済み）

V1 を実装可能な単位に分ける。各単位は**単独で本番に出せる**ことを条件とする。
出せない単位は分け方が間違っている。

---

## 分割の考え方

本番が稼働中のため、途中で止まっても壊れない順序にする。

- 追加だけの作業を先に行う（既存の動作に影響しない）
- 古い経路を消すのは、新しい経路が動いてから
- ひとつの単位で「スキーマ変更」と「判定の置き換え」を同時に行わない

---

## 単位

### U-1 ロールの器を作る

| | |
| --- | --- |
| 満たす要件 | FR-4.1・4.2・4.3・4.6 |
| 内容 | ロール・権限・部員ロール・ロール権限のテーブルを作る。部員でない相手に付けられない制約を入れる |
| 影響 | 追加のみ。既存の動作は変わらない |
| 完了条件 | 現在の管理者2名に相当するロールと割り当てが入っており、`app_accounts.role` と一致する |

既存の `app_accounts.role` はまだ残す。両方が並存する状態を作る。

### U-2 権限で判定する仕組みを作る

| | |
| --- | --- |
| 満たす要件 | FR-4.5、NFR-1.1 |
| 内容 | 「この人がこの権限を持つか」を答える経路を作る。コード中の権限名がすべてデータベースに存在することを検査する仕組みも作る |
| 影響 | 追加のみ。まだ誰も使わない |
| 完了条件 | 検査が動き、存在しない権限名を書くと失敗する |

### U-3 判定を置き換える

| | |
| --- | --- |
| 満たす要件 | FR-4.4・4.5 |
| 内容 | ロール名で判定している17箇所を権限判定に置き換える。RLS ポリシー19箇所も同様に、渡す識別子を権限へ変える |
| 影響 | **サービス再デプロイ。判定の挙動が変わる** |
| 完了条件 | ロール名で判定している箇所がひとつも残っていない。既存の管理者が従来どおり操作できる |

アプリと RLS を同時に変える必要がある。片方だけでは権限が食い違う。

### U-4 旧いロール列を外す

| | |
| --- | --- |
| 満たす要件 | FR-4.3 |
| 内容 | `app_accounts.role` を削除する |
| 影響 | **U-3 が完了していないと壊れる** |
| 完了条件 | 列が存在せず、本番が動作している |

### U-5 引き継ぎを作る

| | |
| --- | --- |
| 満たす要件 | FR-5.1・5.2・5.3、NFR-3.1 |
| 内容 | ロールの付与・剥奪の経路と画面。最後のひとりを外せない制約。変更履歴（追記のみ、トリガーが書く） |

**ここで初めて「引き継ぎができない」という運用上の欠陥が解消する。**

### U-6 退部で権限が外れるようにする

| | |
| --- | --- |

`components.md` Q-4 で申請と部員を分けないと決めたため、これが無いと再入部で権限が復活する。

### U-7 在籍者だけ詳細を出す

| | |

## 順序

依存関係で決まる部分と、選べる部分がある。

```
U-1 → U-2 → U-3 → U-4        ロールの土台（この順でなければならない）
                    ↓
                   U-5, U-6   引き継ぎと退部連動（U-4 完了後）

U-7 → U-8                     表示と一覧（上とは独立）

U-9                           内部整理（いつでも可。U-3 の前だと衝突が減る）

U-10 → U-11                   分離（最後。他が安定してから）
```

### 推奨する順

1. **U-9** — 先にやると U-3 での衝突が減る。外から見た挙動が変わらないため安全
2. **U-1 → U-2 → U-3 → U-4** — ロールの土台
3. **U-5・U-6** — 引き継ぎ。ここで運用上の欠陥が解消する
4. **U-7 → U-8** — 表示と一覧
5. **U-10 → U-11** — 分離

**U-5 までで、いま最も困っていること（引き継ぎがDB操作でしかできない）が解消する。**
U-10・U-11 は可換性のための投資であり、運用上の困りごとは解決しない。後回しでよい。
