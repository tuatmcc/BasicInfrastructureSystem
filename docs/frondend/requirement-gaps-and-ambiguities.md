# 要件定義の定義不足・不明瞭箇所

現行 `docs/` 配下の要件定義を確認し、フロントエンド実装に影響の大きい順で列挙。

## High（実装開始前に明確化が必要）

### 1. 認証・認可の仕様が不足

- 不明点:
  - 認証方式（セッション/JWT/OIDC等）
  - ロールと権限の厳密な対応
  - トークン更新/失効時の扱い
- 影響:
  - ルートガード、表示出し分け、API呼び出し方式が確定できない
- 出典:
  - `docs/MCC基盤システム/Dashboard.md`（認証モジュールはあるが詳細なし）
  - `docs/MCC基盤システム/DiscordConnector.md`（アクセス権限の必要性のみ記載）

### 2. API契約（Request/Response/Error）が不足

- 不明点:
  - 多くのAPIで入出力スキーマが未定義
  - エラー構造とコード体系が未定義
- 影響:
  - 型安全なクライアント生成、フォームバリデーション、エラーハンドリング設計が困難
- 出典:
  - `docs/MCC基盤システム/MemberDatabase/PublicAPI.md`
  - `docs/MCC基盤システム/MemberDatabase/ControlInterface.md`
  - `docs/MCC基盤システム/MemberDatabase/MemberDatabaseController.md`
  - `docs/MCC基盤システム/DiscordConnector/DiscordController/Beta.md`（WIPかつ仕様揺れあり）

### 3. データ識別子の記述に一貫性がない

- 不明/不整合:
  - `ラフ案` は学籍番号をKeyとして記載
  - `MemberDatabase` は uuid 主キー + 学籍番号別カラムを採用
- 影響:
  - フロントのID設計（URLパラメータ、一覧キー、検索軸）に混乱が生じる
- 出典:
  - `docs/MCC基盤システム/ラフ案.md`
  - `docs/MCC基盤システム/MemberDatabase.md`

### 4. 仮登録フローの詳細不足

- 不明点:
  - 「3日?」の確定値、失効後の状態、再招待/再登録導線
- 影響:
  - 仮登録ユーザ向けUI（バッジ、期限警告、再開導線）の設計不可
- 出典:
  - `docs/MCC基盤システム/ラフ案.md`
  - `docs/MCC基盤システム/Dashboard.md`（仮登録放置者の監視要件のみ）

### 5. 受け入れ基準（完了条件）が不足

- 不明点:
  - 画面・機能ごとの「何を満たせば完了か」が未定義
- 影響:
  - 実装完了判定、テストケース策定、レビュー基準が曖昧
- 出典:
  - `docs/MCC基盤システム/MemberDatabase/*`（章はあるが中身未記載）
  - `docs/MCC基盤システム/Dashboard.md`（画面案中心で完了条件なし）

## Medium（早期に明確化すると手戻りが減る）

### 6. UX詳細（遷移・権限拒否時の挙動）が未定義

- 不明点:
  - 未認可アクセス時の遷移先/表示
  - ロール変更直後のUI更新方針
  - 一般部員/管理者の共通画面での具体的表示差分
- 影響:
  - 実装方針が開発者ごとに分岐し一貫性が崩れる
- 出典:
  - `docs/MCC基盤システム/Dashboard.md`

### 7. エラー時のユーザー向け表示方針が未定義

- 不明点:
  - APIエラーをどの粒度で表示するか
  - 再試行可否や案内文の統一ルール
- 影響:
  - UX品質が揃わない、障害時の混乱が増える
- 出典:
  - `docs/MCC基盤システム/DiscordConnector/DiscordDatabaseController/Beta.md`（HTTPコードのみ）

### 8. Discord同期の競合解決方針が不明瞭

- 不明点:
  - DB優先/Discord優先の境界
  - 同期競合時の表示・解決導線
- 影響:
  - 管理画面でのステータス表示や確認操作を定義しにくい
- 出典:
  - `docs/MCC基盤システム/DiscordConnector.md`（整合フローはあるが競合規則なし）

### 9. 非機能要件（性能・可用性）が不足

- 不明点:
  - ページ応答目標、同時利用規模、許容遅延
- 影響:
  - SSR/CSR、キャッシュ、ローディングUXの判断基準が不足
- 出典:
  - `docs/` 全体（明示記載ほぼなし）

## Low（整理しておくと運用が安定）

### 10. 用語の揺れ（日本語/英語、コンポーネント名）

- 例:
  - 操作用インタフェース / ControlInterface
  - 公開API / PublicAPI
- 影響:
  - チケットや画面文言、設計書間の参照に齟齬が出る
- 出典:
  - `docs/MCC基盤システム/*.md` 全般

### 11. 個人情報取扱い要件（表示範囲・保持期間）が不足

- 不明点:
  - 緊急連絡先・保険情報等の閲覧権限、保存期間、削除ポリシー
- 影響:
  - フロントの表示制御や操作制限を確定できない
- 出典:
  - `docs/MCC基盤システム/MemberDatabase.md`

---

## 先に埋めるべき最小セット（提案）

1. 認証/認可仕様（ロール×画面×操作）
2. 主要API 3〜5本の入出力/エラー定義
3. 仮登録フローの確定（期限・失効・再開）
4. 画面ごとの受け入れ基準（最低限）

上記を先に確定すると、フロントエンド実装の初期フェーズ（ルーティング・APIクライアント・主要画面）を手戻り少なく開始できます。
