# フロントエンド要件抽出

`docs/` 配下の要件定義から、フロントエンドの設計・実装に必要な項目を整理。

## 1. 目的・役割

- 各APIサーバのGUI化による管理/操作の簡略化
- 部員の技術レベルに依存しない統一的操作の提供

出典:
- `docs/MCC基盤システム/Dashboard.md` (目的)

## 2. 使用予定技術（フロント）

- フレームワーク: Next.js
- スタイリング: Tailwind CSS
- UIコンポーネント: shadcn/ui
- 認証: Better Auth
- ORM: Drizzle ORM

出典:
- `docs/MCC基盤システム/Dashboard.md` (使用予定の技術)

## 3. フロントエンドの責務

Dashboard サブシステムで主に構築する要素:

- 認証モジュール
- APIクライアント層
- UIコンポーネント群
- ルーティング・ページ構成

出典:
- `docs/MCC基盤システム/Dashboard.md` (システム概要)

## 4. 画面・ルーティング要件

### 4.1 ロール別遷移

- 一般部員: ログイン後 `/dashboard`（マイページ）
- 管理者: ログイン後 `/dashboard`（全ページ利用可）

### 4.2 ページ一覧

- `/dashboard`
  - 全員利用（表示内容はロール分岐）
  - 一般部員: 自分の情報確認・更新
  - 管理者: 未更新部員一覧、Discord名不一致、仮登録放置者の確認
- `/dashboard/members`
  - 管理者のみ
  - 部員一覧、検索、編集、一括操作
- `/dashboard/discord`
  - 管理者のみ
  - ロール・チャンネル権限管理
- `/dashboard/settings`
  - 管理者のみ
  - API接続設定、システム設定

出典:
- `docs/MCC基盤システム/Dashboard.md` (主要画面構成)

## 5. ユーザー像と表示制御

- 一般部員: 自身の登録情報の確認・更新
- 管理者: 部員情報の一括管理、Discord連携設定、各種操作

出典:
- `docs/MCC基盤システム/Dashboard.md` (ユーザー想定)

## 6. システム連携とフロントの統合ポイント

### 6.1 フロントの呼び出し経路

フロント（Web UI）は公開APIを起点に操作する:

- `Web UI -> 公開API -> 操作用インタフェース -> 各コントローラ`

このため、フロントは内部実装よりも公開API仕様への追従を重視する。

出典:
- `docs/MCC基盤システム/DiscordConnector.md` (説明, 制御フロー)
- `docs/MCC基盤システム/MemberDatabase.md` (説明, 制御フロー)

### 6.2 公開APIに関する制約

- 公開APIでは新しいエンドポイントを定義しない
- ControlInterfaceで提供されるAPI範囲内で公開する

出典:
- `docs/MCC基盤システム/DiscordConnector/PublicAPI.md`

## 7. フロント実装に直結する操作要件（ラフ要件含む）

- Discord名変更時に登録情報を手動更新
- 定期的なDiscord名一致確認と不一致通知
- 指定時期まで未更新の部員を非アクティブ扱い
- Discordロールの自動変更
- 新入部員の仮登録→本登録フロー（期限付き仮登録）
- Webからの各種操作（ロール管理、権限管理、アナウンス、投票、リマインド、イベント名簿など）
- API利用クレデンシャル発行・管理

出典:
- `docs/MCC基盤システム/ラフ案.md` (機能要件, やりたいこと)

## 8. API連携上の要件（クライアント実装観点）

`DiscordDatabaseController/Beta.md` から、フロントが意識すべき要件:

- APIプレフィックス: `/api/v1/`
- ステータスコードの基本運用
  - `200 OK`, `201 Created`, `204 No Content`, `400 Bad Request`, `404 Not Found`
- データ形式: JSON
- 主な対象リソース: `/users`, `/roles`, `/categories`, `/channels`
- 一括同期/一括設定を含むエンドポイントあり（例: ロール同期、チャンネル権限設定）

出典:
- `docs/MCC基盤システム/DiscordConnector/DiscordDatabaseController/Beta.md`

## 9. 既存資料で明示的に不足しているフロント要件（抽出結果）

以下は要件として実装に必要だが、現行ドキュメントでは明文化が弱い/未記載:

- アクセシビリティ要件（キーボード操作、コントラスト、スクリーンリーダー対応等）
- i18n（多言語）要件
- フロントの性能要件（初回表示時間、一覧表示件数に対する応答目標など）
- 画面単位の受け入れ条件（完了条件）
- エラー表示の統一方針（ユーザ向け文言・表示形式）

※不足/不明瞭点の詳細は `requirement-gaps-and-ambiguities.md` に記載。
