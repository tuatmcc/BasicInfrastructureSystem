# 追加要件
- はじめにログイン/新規登録画面を表示するようにすること。ログイン画面では、Supabase Authで利用可能なすべてのログイン手段が使えるようにすること。
- 新規登録画面では、`public.members`カラムのうち、`name`、`grade`、`emergency_call`、`student_id`、`student_email`、`insurance`、`some_allergy`の内容を尋ねるようにすること。
- Dashboardが利用するバックエンドのうち、MemberDBの操作に関わる部分は`MemberDatabase/`、Discord操作に関わる部分は`DiscordConnector/`に実装されている。MemberDBで利用可能なエンドポイントの一覧は`MemberDatabase/README.md`に、Discord操作に必要なエンドポイントは`docs/MCC基盤システム/DiscordConnector/DiscordController/Beta.md`記載されている。
原則、DashboardからSupabaseとDiscordを直接操作せず、以上に示した既存のエンドポイントを用いること。ただし、例外としてログイン時のSupabaseへのアクセスは許可する。

今の実装だと、新規登録のためにDiscord候補を取得する必要があるにもかかわらず、ログインを押すとSupabase側にデータがないため最初のログインページに戻されてしまい、認証ができず、Discord候補を取得できないため、先に進めません。
この問題を解決するために、新規登録画面では、どの手段を用いて登録するか(想定する手段は現状のログイン画面と同じ)のみを尋ねるようにして、下部のボタンは「登録」と表示するようにしてください。登録ボタンを押し、正常にSupabase Authの認証テーブルに追加された場合には、ログイン画面から「入部届画面」に遷移するようにしてください(「入部届画面」は現状存在しないので新たに実装してください。表示内容は現状の部員情報取得とほぼ同じで構いませんが、「Discord表示名で検索」と書いてある入力欄は、プルダウンメニューの中で表示される(プルダウンをクリックして表示されるダイアログ内の一番上に検索用ダイアログを配置し、その下に候補一覧が並ぶスクロール可能領域が表示される)ようにしてください。また、学年選択についても仕様変更があります。詳細は最後に伝えます。)
入部届画面の最下部には「登録」ボタンを表示し、のすべてのフィールドが適切に設定された場合にグレーアウトを解除し、不備がある場合にはグレーアウトするようにしてください。
